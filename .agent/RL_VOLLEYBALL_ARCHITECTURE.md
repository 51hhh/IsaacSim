## 1. 项目概述

### 1.1 目标

在 NVIDIA IsaacSim 5.1.0 中训练一个强化学习（RL）策略，使排球机器人能够：

1. **感知排球**：通过视觉系统检测排球位置与速度，预测飞行轨迹
2. **移动拦截**：控制四轮全向底盘快速移动到拦截位置
3. **击球回球**：控制 Delta 机械臂调整球拍角度，在正确时刻击球，将球打回对方场地
4. **持续对打**：具备连续接球-回球能力，实现多回合对打

### 1.2 核心设计原则

1. **光栅触发反射弧**：RL 负责"瞄准与预位"，光栅硬件负责"精确时机触发"（v3.0 核心）
2. **低延迟优先**：针对排球高速特点，整体延迟控制在 < 50 ms
3. **训练部署共享 EKF**：同一个扩展卡尔曼滤波器在仿真训练和实机部署中使用，减小 sim-to-real gap
4. **感知噪声 + 延迟嵌入训练**：将真实系统的检测概率、测量噪声、执行器延迟模型嵌入训练环境
5. **约束 RL**：通过 N-P3O（约束 PPO）实施硬件电流约束，而非软惩罚
6. **主动感知**：独立的摄像头云台 + RL 控制，学习最优的视线追踪策略

### 1.3 参考方法论

本项目的方法论直接基于 ETH Zurich 的羽毛球机器人论文，做了以下适配：

| 论文方法 | 本项目适配 |
|---------|-----------|
| 四足机器人（ANYmal）+ 机械臂 | 四轮全向底盘 + Delta 臂（3+1 电机）+ 相机云台 |
| 羽毛球穿梭球 | 排球（更大、更重、气动特性不同） |
| IsaacGym（已停止维护） | IsaacSim 5.1.0 + Isaac Lab（官方推荐替代） |
| 12 DOF 腿 + 6 DOF 臂（18 DOF） | 3 DOF 底盘 + 2 DOF 击球臂 + 1 DOF 相机（共 9 电机） |
| 关节力矩直接控制 | **光栅触发反射弧 — 见 1.4 节** |
| 基座俯仰主动感知 | **相机云台 PD 跟踪（非 RL 控制）** |

### 1.4 控制架构：光栅触发击球反射弧

#### 核心问题：时空撕裂

混合架构（底盘高层 + 手臂力矩）存在**同步噩梦**：
- **底盘**：cmd_vel → CAN → 电机 PID → 克服惯性 → 达到目标速度，是**二阶系统**，响应延迟 100-200 ms
- **手臂**：力矩控制几乎零延迟（< 10 ms）

**后果**：RL 同时下达"向前冲 + 挥拍"时，手已挥出，车还没动。RL 会学到奇怪的"提前挥拍"策略，但这种时间差补偿在 Sim-to-Real 时会失效。

#### 解决方案：光栅触发反射弧

利用球拍前方的**光栅传感器**作为硬件触发器，将控制分为两层：


#### RL 策略职责（简化）

| 职责 | 输出 | 频率 | 说明 |
|------|------|------|------|
| **底盘导航** | cmd_vel (vx, vy, wz) | 100 Hz | 把球拍中心送到球的飞行轨迹上 |
| **手臂预备** | z_ready | 100 Hz | Delta 臂预备高度 |
| **角度预备** | pitch_ready | 100 Hz | 击球板俯仰角，决定回球方向 |
| **力度设定** | strike_intensity | 100 Hz | 击球力度（0-1，映射到力矩曲线） |

**RL 不需要**：
- 精确的击球时机控制（光栅触发）
- 云台俯仰控制（PD 跟踪）
- 复杂的手臂轨迹规划

#### 底层反射层实现

```cpp
// 底层击球反射控制器 (运行在电机驱动板或专用 MCU, 1000 Hz)
class StrikeReflexController {
public:
    // RL 设定的参数（100 Hz 更新）
    float z_ready;              // 预备高度 (m)
    float pitch_ready;          // 预备角度 (rad)
    float strike_intensity;     // 击球力度 (0-1)
    
    // 预设的击球力矩曲线 (可由 RL 选择或参数化)
    TorqueProfile torque_profiles[3] = {
        {.duration_ms = 50, .peak_torque = 8.0,  .name = "轻击"},
        {.duration_ms = 30, .peak_torque = 15.0, .name = "中击"},
        {.duration_ms = 20, .peak_torque = 25.0, .name = "扣杀"},  // 40A 爆发
    };
    
    void update(bool grating_triggered) {
        if (grating_triggered && !strike_in_progress) {
            // 光栅触发！开始击球
            strike_in_progress = true;
            strike_start_time = now();
            selected_profile = selectProfile(strike_intensity);
        }
        
        if (strike_in_progress) {
            // 执行力矩曲线
            float t = now() - strike_start_time;
            float torque = selected_profile.getTorque(t);
            applyDeltaTorque(torque);  // 3 电机协同施加 Z 方向力
            
            if (t > selected_profile.duration_ms) {
                strike_in_progress = false;
                // 击球完成，恢复预备姿态
            }
        } else {
            // 保持预备姿态（位置 PD 控制）
            holdPosition(z_ready, pitch_ready);
        }
    }
};
```

#### 底盘动力学建模改进

为解决 Sim-to-Real 差距，底盘仿真需添加**一阶低通滤波**模拟物理响应：

```python
class ChassisLowPassFilter:
    """
    模拟底盘的物理惯性和 PID 响应
    比简单的 buffer delay 更真实
    """
    def __init__(self, tau=0.1, dt=0.01):
        """
        tau: 时间常数 (s)，越大响应越慢
             GM3508 + 全向轮实测约 80-150 ms
        dt:  仿真步长 (s)
        """
        self.tau = tau
        self.alpha = dt / (tau + dt)  # 低通滤波系数
        self.current_vel = np.zeros(3)  # [vx, vy, wz]
    
    def filter(self, target_vel):
        """
        target_vel: RL 输出的目标速度
        return: 实际执行的速度（经过滤波）
        """
        # 一阶低通滤波: v_actual = α * v_target + (1-α) * v_prev
        self.current_vel = (
            self.alpha * target_vel + 
            (1 - self.alpha) * self.current_vel
        )
        return self.current_vel
    
    def set_tau_random(self, tau_range=(0.05, 0.15)):
        """域随机化：随机设置时间常数"""
        self.tau = np.random.uniform(*tau_range)
        self.alpha = self.dt / (self.tau + self.dt)


# 在环境中使用
class VolleyballEnv:
    def __init__(self):
        self.chassis_filter = ChassisLowPassFilter(tau=0.1)
    
    def step(self, actions):
        # RL 输出的目标速度
        target_vel = actions[:3] * self.max_vel
        
        # 应用低通滤波（模拟底盘惯性）
        actual_vel = self.chassis_filter.filter(target_vel)
        
        # 用滤波后的速度驱动仿真
        self.robot.set_base_velocity(actual_vel)
```

#### 为什么这个架构能工作

| 传统方案的问题 | 光栅反射弧的解决 |
|--------------|----------------|
| RL 需要精确预测击球时机 | 光栅硬件精确触发，RL 只管位置 |
| 底盘 200ms 延迟 vs 手臂 10ms | 解耦！底盘慢慢跑，手臂瞬间爆发 |
| 仿真难以精确建模时间同步 | 时间同步由硬件保证，仿真只需建模位置 |
| 击球"软绵绵"（PID 限流） | MIT 模式 40A 瞬时爆发 |

#### 大拍面的容错优势

| 参数 | 值 | 容错效果 |
|------|-----|---------|
| 拍面尺寸 | 球的 2-3 倍（约 50-60 cm） | ±10 cm 位置误差仍能击中 |
| 底盘定位精度 | 正交编码器 + 陀螺仪 ~5 cm | 在容错范围内 |
| 光栅覆盖范围 | 与拍面等宽 | 球到哪里都能触发 |

```
场景假设:
```

```python
# Delta 臂高度控制 (简化模型)
# 输入: 目标 Z 高度 z_target
# 输出: 3 个电机的角度 [θ1, θ2, θ3]

def delta_inverse_kinematics_simplified(z_target):
    """
    简化的 Delta 逆运动学
    假设 X=Y=0 (中心位置)，只控制 Z 高度
    """
    # 几何参数
    L_upper = 0.30  # 上臂长度 (m)
    L_lower = 0.50  # 下臂长度 (m)
    r_base = 0.15   # 基座半径 (m)
    r_platform = 0.05  # 运动平台半径 (m)
    
    # 计算电机角度 (3 个电机对称布置)
    theta = calculate_angle(z_target, L_upper, L_lower, r_base, r_platform)
    return [theta, theta, theta]  # 对称情况下 3 个角度相同
```

### 3.4 摄像头云台（PD 追踪控制）

#### 问题背景

排球飞行轨迹跨度大（从高空到地面），固定安装的摄像头存在以下问题：
1. **视场角限制**：即使广角镜头（90° FOV），也无法同时覆盖高空和地面
2. **分辨率损失**：广角镜头远距离目标像素少，检测精度下降
3. **运动模糊**：机器人快速移动时，固定相机的图像容易模糊

#### 为什么不用 RL 控制云台

**风险**：RL 倾向于通过高频抖动来获取更多信息：
- **视觉模糊**：相机快速俯仰导致 Motion Blur，YOLO 检测失效
- **EKF 爆炸**：相机抖动时编码器延迟，坐标变换不准，球位置估计乱跳
- **策略震荡**："看不到球 → 乱转找球 → 更看不清" 死循环

#### 推荐方案：传统 PD 追踪控制

```
┌─────────────────────────────────────────────────────────────────────────────────┐
│                    相机云台 PD 控制（独立于 RL，1000 Hz）                         │
│                                                                                 │
│   输入: 球的 EKF 估计位置 (ball_x, ball_y, ball_z)                               │
│                                                                                 │
│   目标俯仰角:                                                                   │
│     target_pitch = atan2(ball_z - camera_z, ball_distance_xy)                  │
│                  = atan2(ball_z - camera_z, sqrt(ball_x² + ball_y²))           │
│                                                                                 │
│   PD 控制器:                                                                    │
│     error = target_pitch - current_pitch                                        │
│     torque = Kp * error + Kd * (d_error/dt)                                     │
│                                                                                 │
│   参数:                                                                         │
│     Kp = 50.0   (比例增益)                                                      │
│     Kd = 5.0    (微分增益，平滑运动）                                            │
│     max_pitch_rate = 180 °/s (角速度限幅，防止模糊)                              │
└─────────────────────────────────────────────────────────────────────────────────┘
```

#### 云台控制伪代码

```cpp
// 独立的相机云台控制器（运行在 MCU 或独立线程）
class CameraGimbalController {
public:
    // PD 参数
    float Kp = 50.0f;
    float Kd = 5.0f;
    float max_rate = 180.0f * DEG2RAD;  // rad/s
    
    // 球状态（从 EKF 订阅）
    float ball_x, ball_y, ball_z;
    
    void update(float dt) {
        // 1. 计算目标俯仰角
        float dx = sqrt(ball_x * ball_x + ball_y * ball_y);
        float dz = ball_z - camera_height;
        float target_pitch = atan2(dz, dx);
        
        // 2. 限幅到物理范围
        target_pitch = clamp(target_pitch, -30*DEG2RAD, 60*DEG2RAD);
        
        // 3. PD 控制
        float error = target_pitch - current_pitch;
        float d_error = (error - last_error) / dt;
        float torque = Kp * error + Kd * d_error;
        
        // 4. 角速度限幅（防止运动模糊）
        float desired_rate = torque / motor_inertia;
        desired_rate = clamp(desired_rate, -max_rate, max_rate);
        
        // 5. 发送到电机
        set_motor_velocity(desired_rate);
        
        last_error = error;
    }
};
```

#### 云台参数

| 参数 | 值 | 说明 |
|------|-----|------|
| 俯仰范围 | -30° ~ +60° | 向下 30°，向上 60° |
| 最大角速度 | **180°/s** | **限幅！** 防止运动模糊 |
| 电机型号 | GM6020 | 精度高，扭矩足够 |
| 控制频率 | 1000 Hz | 高频 PD 保证平滑 |
| 安装位置 | 机器人顶部中央 | 最佳视野 |

#### 云台 vs RL 控制对比

| 方面 | RL 控制云台 | PD 追踪云台（推荐） |
|------|-----------|-------------------|
| 训练复杂度 | +1 维动作空间 | 无需训练 |
| 响应速度 | 100 Hz | 1000 Hz（更快） |

#### 光栅传感器观测说明

```python
def compute_grating_observation(ball_pos, grating_config):
    """
    光栅光幕检测：当球进入光幕区域时返回距离
    
    Args:
        ball_pos: [3] 球在机器人基座系的位置
        grating_config: 光栅配置 (位置, 范围)
    
    Returns:
        grating_dist: 球到击球面的距离，若未检测到则为 -1
    """
    # 检查球是否在光栅检测范围内
    if is_in_grating_beam(ball_pos, grating_config):
        # 返回球到击球面的距离（前向距离）
        return ball_pos[0] - grating_config.beam_x
    else:
        return -1.0
```

**设计考量**：
- 光栅距离让 RL 能感知球何时接近击球区域
- 当 `grating_dist > 0` 且较小时，RL 应确保手臂已就位
- 光栅触发击球是硬件层面的，但 RL 需要了解触发状态以协调底盘

**总计**: ~31 维

| `perception_error` | 3 | m | EKF 估计误差（= 估计值 - 真值） |
| `targets_remaining` | 1 | - | 本 episode 剩余击球目标数 |
| `next_ball_distance` | 1 | m | 到下一个球的距离 |
| `domain_rand_params` | ~5 | - | 当前域随机化参数（摩擦系数、球质量等） |

**设计依据**（参考论文 Table S3）：Asymmetric Actor-Critic 架构。Actor 只使用部署时可获取的观测（经过 EKF 滤波的球状态），Critic 获取额外的特权信息用于辅助训练。这样做的好处是：
- Actor 在训练时就学会在有感知噪声的条件下决策
- Critic 用 ground truth 提供更准确的价值估计，加速训练收敛

```python
class ActionMapperGratingTrigger:
    """
    光栅触发架构的动作映射器
    RL 只负责瞄准和蓄力，击球由光栅触发
    """
    
    def __init__(self):
        # 底盘参数
        self.max_linear_vel = 2.5      # m/s
        self.max_angular_vel = 3.0     # rad/s
        
        # Delta 臂参数
        self.z_center = 0.25           # m (中心高度)
        self.z_range = 0.15            # m (可调范围 ±)
        
        # 击球板参数
        self.max_paddle_pitch = 60.0   # deg
        
        # 击球力度映射
        self.strike_profiles = {
            -1.0: {"name": "轻推", "torque": 8.0,  "duration_ms": 50},
            0.0:  {"name": "中击", "torque": 15.0, "duration_ms": 30},
            1.0:  {"name": "扣杀", "torque": 25.0, "duration_ms": 20},
        }
    
    def map_actions(self, raw_actions):
        """
        raw_actions: [batch, 6], 范围 [-1, 1]
        返回: 物理命令 dict
        """
        return {
            # 底盘：立即执行（经过低通滤波）
            "cmd_vel": {
                "vx": raw_actions[:, 0] * self.max_linear_vel,
                "vy": raw_actions[:, 1] * self.max_linear_vel,
                "wz": raw_actions[:, 2] * self.max_angular_vel,
            },
            
            # 手臂预备位置：保持在此位置等待光栅触发
            "arm_ready": {
                "z_target": self.z_center + raw_actions[:, 3] * self.z_range,
                "pitch_target": raw_actions[:, 4] * self.max_paddle_pitch,
            },
            
            # 击球参数：光栅触发时使用
            "strike": {
                "intensity": raw_actions[:, 5],  # -1 轻推, 0 中击, +1 扣杀
            },
        }
    
    def get_strike_profile(self, intensity):
        """根据 intensity 插值获取击球力矩曲线"""
        # 线性插值
        if intensity < 0:
            alpha = intensity + 1  # 0 to 1
            low = self.strike_profiles[-1.0]
            high = self.strike_profiles[0.0]
        else:
            alpha = intensity      # 0 to 1
            low = self.strike_profiles[0.0]
            high = self.strike_profiles[1.0]
        
        return {
            "torque": low["torque"] + alpha * (high["torque"] - low["torque"]),
            "duration_ms": low["duration_ms"] + alpha * (high["duration_ms"] - low["duration_ms"]),
        }
```

#### 光栅触发时刻奖励（仅在光栅触发击球瞬间激活）

| 奖励项 | 公式 | 权重 | 触发条件 |
|--------|------|------|---------|
| **中心命中 Bonus** | `50.0 × exp(-d²/0.01²)` | 50.0 | 击中球且 d < 5cm |
| 边缘击中 | `30.0 × (1 - d/paddle_radius)` | 30.0 | 击中球但偏离中心 |
| 光栅触发未击中 | `-5.0` | -5.0 | 光栅触发但球未触拍 |
| 回球成功 | `+100.0` | 100.0 | 球落入对方半场 |
| 回球出界 | `-20.0` | -20.0 | 球被击出但出界 |

```python
def compute_strike_reward(contact_info, paddle_config, ball_landing):
    """
    光栅触发击球时刻的奖励计算
    
    Args:
        contact_info: 碰撞信息 (有无接触, 接触点位置)
        paddle_config: 拍面配置 (中心位置, 半径)
        ball_landing: 球落点信息
    """
    reward = 0.0
    
    if not contact_info.has_contact:
        # 光栅触发了但没打到球 → 惩罚
        return -5.0
    
    # 计算击球点到拍面中心的距离
    contact_to_center = contact_info.point - paddle_config.center
    d = np.linalg.norm(contact_to_center)
    
    # === 核心: 中心命中 Bonus ===
    # σ = 1cm，打在中心 reward ≈ 50，偏离 2cm reward ≈ 7
    center_bonus = 50.0 * np.exp(-(d ** 2) / (0.01 ** 2))
    reward += center_bonus
    
    # 基础击中奖励 (与距中心的距离成反比)
    edge_reward = 30.0 * max(0, 1 - d / paddle_config.radius)
    reward += edge_reward
    
    # 回球成功奖励 (稀疏但最高)
    if ball_landing.in_opponent_court:
        reward += 100.0
    elif ball_landing.out_of_bounds:
        reward -= 20.0
    
    return reward
```

#### 持续奖励（每步都计算，100 Hz）

| 奖励项 | 公式 | 权重 | 目的 |
|--------|------|------|------|
| **预位准备度** | `exp(-‖ee_pos - intercept_pos‖² / σ²)` | 5.0 | 鼓励提前把手臂伸到拦截点 |
| 拦截路径覆盖 | `+1 if paddle blocks ball trajectory` | 2.0 | 拍面在球的飞行路径上 |
| 球追踪距离 | `exp(-‖robot_pos - ball_intercept_xy‖²)` | 3.0 | 底盘靠近拦截点 XY |
| 动作变化率惩罚 | `-‖a_t - a_{t-1}‖²` | -0.03 | 动作平滑 |
| 关节力矩惩罚 | `-‖τ‖²` | -1e-5 | 节能 |
| 出界惩罚 | `-5.0 (if out of court)` | -5.0 | 保持在己方场地 |
| 静止奖励（无球时） | `exp(-‖v_base‖²)` | 2.0 | 无球时保持静止节能 |

#### 与旧版奖励的对比

| 方面 | 旧版（RL 控制击球时机） | 新版（光栅触发 + 中心命中） |
|------|----------------------|--------------------------|
| 击球时机奖励 | δ(t-T) 激活 | **光栅触发激活** |
| 击球位置奖励 | 末端位置跟踪 | **中心命中 Bonus** |
| 核心理念 | RL 学时机 | RL 学位置，硬件管时机 |
| 训练难度 | 时间+空间耦合 | **解耦，更简单** |

#### 奖励设计要点

1. **中心命中 Bonus 是关键**：大拍面（2-3 倍球直径）提供容错，但打中心才能精准控制回球方向
2. **光栅触发简化时机学习**：RL 不用学 "什么时候挥拍"，只需学 "把手伸到哪里"
3. **预位准备度**：连续奖励引导 RL 提前到位，而非最后时刻急挥
4. **稀疏 + 密集混合**：回球成功（100）是稀疏大奖，预位准备度（5.0/step）提供梯度

#### 排球 vs 羽毛球差异

#### 碰撞物理模型

```python
class VolleyballCollisionModel:
    """
    排球碰撞物理模型 (IsaacSim 配置)
    参考文献: "Physics of Volleyball" - University Physics Lab
    """
    
    def __init__(self):
        # 排球材质参数
        self.ball = {
            "mass": 0.270,           # kg
            "radius": 0.105,         # m
            "restitution": 0.75,     # 恢复系数（与硬板碰撞）
            "friction": 0.4,         # 摩擦系数
            "stiffness": 8000,       # N/m (接触刚度)
            "damping": 100,          # Ns/m (接触阻尼)
        }
        
        # 击球硬板材质参数
        self.paddle = {
            "restitution": 0.85,     # 硬板恢复系数略高
            "friction": 0.5,
            "stiffness": 50000,      # 硬板刚度高
            "damping": 50,
        }
    
    def compute_post_collision_velocity(self, v_ball, v_paddle, normal):
        """
        计算碰撞后球的速度
        基于冲量-动量定理 + 恢复系数
        """
        # 相对速度（沿法向）
        v_rel = v_ball - v_paddle
        v_rel_n = np.dot(v_rel, normal)
        
        # 冲量计算
        e = self.ball["restitution"] * self.paddle["restitution"]
        m_ball = self.ball["mass"]
        m_paddle = float('inf')  # 假设击球板质量无限大（固定在电机上）
        
        J = -(1 + e) * v_rel_n * m_ball * m_paddle / (m_ball + m_paddle)
        
        # 碰撞后速度
        v_ball_post = v_ball + J / m_ball * normal
        
        # 考虑旋转（简化：忽略旋转传递）
        return v_ball_post
```

### 6.3 感知噪声模型（训练时嵌入）

参考论文的核心创新之一：将真实视觉系统的不完美性建模为距离和角速度的函数，嵌入训练环境。

#### 检测概率模型

```
P_detect(d, ω) = P_0 × exp(-α_d × d) × exp(-α_ω × ω)

参数：
  P_0:   基础检测概率（近距离、静止时），约 0.95
  d:     球到相机的距离 (m)
  ω:     球的角速度（像素/帧）
  α_d:   距离衰减系数（需标定）
  α_ω:   角速度衰减系数（需标定）

效果：
  - 球越远，检测概率越低
  - 球运动越快（在图像中），检测概率越低
  - 模拟真实检测器在困难条件下的丢失
```

#### 测量噪声模型

```
σ_measure(d) = σ_0 + σ_d × d²

参数：
  σ_0:   基础测量噪声（像素），约 2 px
  σ_d:   距离相关噪声增长系数

在训练中：
  detected = random() < P_detect(d, ω)
  if detected:
      measurement = true_pos + N(0, σ_measure(d))
      EKF.update(measurement)
  else:
      EKF.predict_only()  // 无测量更新，仅预测
```

### 7.2 随机化策略

- **episode 级别随机化**：球质量、阻力系数、摩擦系数、底盘质量等在每个 episode 开始时采样一次
- **step 级别随机化**：控制延迟、感知噪声在每步独立采样
- **渐进式引入**：训练初期使用较小的随机化范围，随训练进展逐步扩大（Curriculum）
- **Critic 可见**：所有域随机化参数作为特权观测传入 Critic 网络

#### IsaacSim 中引入延迟的方法

```python
# isaaclab_training/envs/volleyball_env.py

class VolleyballEnvCfg(DirectRLEnvCfg):
    """环境配置：包含延迟设置"""
    
    # 延迟配置
    class delay:
        # 1. 观测延迟（感知延迟）
        observation_delay_steps: int = 2    # 观测延迟步数 (每步 10ms → 20ms)
        observation_delay_range: tuple = (0, 4)  # 随机化范围
        
        # 2. 动作延迟（控制+执行延迟）  
        action_delay_steps: int = 3         # 动作延迟步数 (每步 10ms → 30ms)
        action_delay_range: tuple = (0, 5)  # 随机化范围


class VolleyballEnv(DirectRLEnv):
    """排球环境：实现延迟机制"""
    
    def __init__(self, cfg: VolleyballEnvCfg, ...):
        super().__init__(cfg, ...)
        
        # 初始化延迟缓冲区
        max_obs_delay = cfg.delay.observation_delay_range[1]
        max_act_delay = cfg.delay.action_delay_range[1]
        
        self.obs_buffer = torch.zeros(
            (self.num_envs, max_obs_delay + 1, self.obs_dim), device=self.device
        )
        self.action_buffer = torch.zeros(
            (self.num_envs, max_act_delay + 1, self.action_dim), device=self.device
        )
        
        # 每个环境的随机延迟值
        self.obs_delay = torch.zeros(self.num_envs, dtype=torch.long, device=self.device)
        self.action_delay = torch.zeros(self.num_envs, dtype=torch.long, device=self.device)
    
    def _sample_delays(self, env_ids):
        """在 episode 重置时采样延迟值"""
        num_envs = len(env_ids)
        
        # 观测延迟随机化
        self.obs_delay[env_ids] = torch.randint(
            self.cfg.delay.observation_delay_range[0],
            self.cfg.delay.observation_delay_range[1] + 1,
            (num_envs,), device=self.device
        )
        
        # 动作延迟随机化
        self.action_delay[env_ids] = torch.randint(
            self.cfg.delay.action_delay_range[0],
            self.cfg.delay.action_delay_range[1] + 1,
            (num_envs,), device=self.device
        )
    
    def _apply_observation_delay(self, current_obs):
        """应用观测延迟：返回历史观测"""
        # 将当前观测推入缓冲区
        self.obs_buffer = torch.roll(self.obs_buffer, shifts=1, dims=1)
        self.obs_buffer[:, 0, :] = current_obs
        
        # 根据每个环境的延迟值，取出对应的历史观测
        delayed_obs = torch.zeros_like(current_obs)
        for i in range(self.num_envs):
            delay = self.obs_delay[i]
            delayed_obs[i] = self.obs_buffer[i, delay]
        
        return delayed_obs
    
    def _apply_action_delay(self, current_action):
        """应用动作延迟：返回历史动作用于执行"""
        # 将当前动作推入缓冲区
        self.action_buffer = torch.roll(self.action_buffer, shifts=1, dims=1)
        self.action_buffer[:, 0, :] = current_action
        
        # 根据每个环境的延迟值，取出对应的历史动作
        delayed_action = torch.zeros_like(current_action)
        for i in range(self.num_envs):
            delay = self.action_delay[i]
            delayed_action[i] = self.action_buffer[i, delay]
        
        return delayed_action
    
    def step(self, actions):
        """重写 step 函数，加入延迟"""
        # 1. 动作延迟：执行的是之前的动作
        delayed_actions = self._apply_action_delay(actions)
        
        # 2. 执行物理仿真
        self._apply_actions(delayed_actions)
        self._sim_step()
        
        # 3. 获取当前观测
        current_obs = self._get_observations()
        
        # 4. 观测延迟：返回的是历史观测
        delayed_obs = self._apply_observation_delay(current_obs)
        
        # 5. 计算奖励（使用真实状态，非延迟）
        rewards = self._compute_rewards()
        dones = self._check_terminations()
        
        return delayed_obs, rewards, dones, {}
```

#### 底盘低通滤波器（Sim2Real 关键！）

```python
class ChassisLowPassFilter:
    """
    模拟真实全向轮底盘的动态响应
    一阶低通滤波器: v_dot = (v_cmd - v_actual) / τ
    
    为什么需要？
    - 全向轮有惯性、电机有限流、轮子有打滑
    - 2.5 m/s 指令不会瞬间达到，需要 100-200ms 过渡
    - 如果仿真是理想响应，RL 会学到依赖瞬间响应的策略
    """
    
    def __init__(self, num_envs, device, dt=0.01):
        """
        Args:
            num_envs: 并行环境数
            device: torch device
            dt: 仿真步长 (s)
        """
        self.dt = dt
        self.device = device
        
        # 当前实际速度状态
        self.v_actual = torch.zeros((num_envs, 3), device=device)  # [vx, vy, wz]
        
        # 时间常数（域随机化）
        # τ = 80-150 ms，对应全向轮底盘的响应延迟
        self.tau = torch.zeros(num_envs, device=device)
    
    def reset(self, env_ids):
        """重置指定环境的滤波器状态"""
        self.v_actual[env_ids] = 0.0
        # τ 域随机化
        self.tau[env_ids] = torch.empty(len(env_ids), device=self.device).uniform_(0.08, 0.15)
    
    def step(self, v_cmd):
        """
        应用低通滤波
        
        Args:
            v_cmd: [num_envs, 3] 指令速度 [vx, vy, wz]
        
        Returns:
            v_actual: [num_envs, 3] 经过滤波后的实际速度
        """
        # 一阶低通滤波: dv/dt = (v_cmd - v_actual) / τ
        # 离散化: v_actual += (v_cmd - v_actual) * (dt / τ)
        
        alpha = self.dt / self.tau.unsqueeze(1)  # [num_envs, 1]
        alpha = alpha.clamp(max=1.0)  # 防止 dt > τ 时不稳定
        
        self.v_actual = self.v_actual + (v_cmd - self.v_actual) * alpha
        
        return self.v_actual

# 集成到环境中
class VolleyballEnvWithLowPass(VolleyballEnv):
    def __init__(self, cfg, ...):
        super().__init__(cfg, ...)
        self.chassis_filter = ChassisLowPassFilter(self.num_envs, self.device, dt=self.dt)
    
    def _apply_actions(self, actions):
        """重写动作应用，加入低通滤波"""
        
        # 底盘动作 → 经过低通滤波
        chassis_cmd = actions[:, :3]  # [vx, vy, wz]
        chassis_actual = self.chassis_filter.step(chassis_cmd)
        
        # 手臂动作 → 直接执行（响应快，无需滤波）
        arm_cmd = actions[:, 3:]
        
        # 应用到仿真
        self._set_chassis_velocity(chassis_actual)
        self._set_arm_target(arm_cmd)
```

#### τ 参数标定方法

```python
def calibrate_chassis_tau(robot):
    """
    在真实机器人上标定时间常数 τ
    方法：发送阶跃指令，测量响应曲线
    """
    # 1. 从静止发送指令
    cmd_vel = 2.0  # m/s
    robot.send_cmd_vel(cmd_vel, 0, 0)
    
    # 2. 记录速度响应
    t_samples = []
    v_samples = []
    for _ in range(50):  # 500ms
        t_samples.append(time.time())
        v_samples.append(robot.get_actual_velocity()[0])
        time.sleep(0.01)
    
    # 3. 拟合一阶系统响应: v(t) = v_cmd * (1 - exp(-t/τ))
    from scipy.optimize import curve_fit
    
    def first_order_response(t, tau):
        return cmd_vel * (1 - np.exp(-t / tau))
    
    tau_fit, _ = curve_fit(first_order_response, t_samples, v_samples)
    
    print(f"标定结果: τ = {tau_fit[0] * 1000:.1f} ms")
    return tau_fit[0]
```

#### 延迟对训练的影响

| 延迟级别 | 典型值 | 训练效果 | 部署表现 |
|---------|--------|---------|---------|
| 无延迟 | 0 ms | 收敛快，奖励高 | **部署后性能骤降**（过拟合理想条件） |
| 低延迟 | 10-30 ms | 略慢收敛，奖励稍低 | 在低延迟硬件上表现好 |
| **中延迟（推荐）** | **20-50 ms** | 稳定收敛 | **兼容大多数硬件** |
| 高延迟 | 50-100 ms | 收敛困难，奖励低 | 适用于高延迟系统 |

#### 延迟感知的策略行为

良好的策略应该学会：
1. **预判**：提前行动以补偿延迟
2. **保守**：避免依赖即时反馈的危险动作
3. **平滑**：避免高频抖动（会被延迟放大）

## 8. Sim-to-Real 迁移

### 8.1 迁移策略

| 策略 | 具体措施 |
|------|---------|
| **共享 EKF** | 训练和部署使用完全相同的 EKF 代码，球状态估计行为一致 |
| **感知噪声嵌入** | 训练中加入与真实系统匹配的检测概率和测量噪声模型 |
| **域随机化** | 大范围物理参数随机化，覆盖真实系统的不确定性 |
| **高层命令** | RL 输出 vx/vy/wz + pitch，不直接控制电机，避免 sim-to-real gap 最大的低层动力学 |
| **动作平滑** | 动作变化率惩罚 + 低通滤波，避免不现实的高频抖动 |
| **控制延迟随机化** | 训练中随机添加 0-30ms 延迟，匹配真实系统的通信/计算延迟 |

### 8.2 ONNX 部署流程

```
训练完成
    │
    ▼
导出 Actor 网络为 ONNX 格式
    │
    ▼
rl_policy_node 加载 ONNX 模型
    │
    ├── 使用 onnxruntime (Python) 或 onnxruntime (C++) 推理
    ├── 输入: actor_obs (28 维 float32 tensor)
    ├── 输出: actions (4 维 float32 tensor, [-1, 1])
    │
    ▼
动作缩放 + 发布到 /cmd_vel 和 /delta_arm_cmd
```
